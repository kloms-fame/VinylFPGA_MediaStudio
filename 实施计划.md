# VinylFPGA Media Studio Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development for isolated implementation tasks and two-stage review. Steps use checkbox syntax for tracking. User has approved implementation; no additional design approval is needed.

**Goal:** Deliver a self-contained Windows portable media organizer, image builder, image-readback preview and verified SD writer in the independent MediaStudio folder.

**Architecture:** A Python loopback HTTP service owns project files and build jobs. Local HTML/CSS/JS provides editing, media playback and image preview. Independent FAT32/build, ROM/render and disk modules expose narrow APIs; bundled vendor helpers retain known format and write safeguards.

**Tech Stack:** Python stdlib HTTP/unittest/Win32 ctypes, Pillow, bundled FFmpeg/FFprobe, PyInstaller folder distribution. No Node/runtime CDN. Development-only RTL pixel checks use installed Icarus Verilog or ModelSim.

All relative paths below are beneath `VinylFPGA_MediaStudio/`. Worktree: `.worktrees/media-studio`; original RTL stays unmodified. Existing 31 tool-contract tests pass as baseline.

`release.json` contains schema, mode, image path/hash/bytes, tracks with converted file names, duration/sample counts, ROM profile path, ROM hash map, firmware status (`frozen` or `requires_build`), source hashes and validation details. Always provide `rom/` beside release, whether frozen or custom. Less than four active tracks: populate four ROM metadata slots, empty inactive slots; INDEX count equals active tracks.

Exact release contract (all paths relative to the directory containing release.json; optional media are `null`, never empty pseudo-records):

```json
{"schema":1,"name":"album","mode":"frozen",
 "image":{"path":"card.img","sha256":"64 hex","bytes":67108864},
 "tracks":[{"slot":0,"title":"requested title","artist":"requested artist",
   "duration_ms":1000,"samples":48000,
   "audio":{"path":"converted/AUDIO.PCM","lba":100,"bytes":96000,"sha256":"64 hex"},
   "cover":{"path":"converted/PIC1.BMP","lba":300,"bytes":921654,"sha256":"64 hex"},
   "mv":null,"lyrics":[[0,"text"]]}],
 "background":{"lba":1000,"frames":6,"frame_bytes":614400},
 "rom":{"path":"rom","files_sha256":{"song_text_rom.v":"64 hex"}},
 "firmware":{"status":"frozen","compatible":true,"differences":[],"bit_sha256":"64 hex"},
 "validation":{"passed":true},"sources":{}}
```

MV records use the same `path/lba/bytes/sha256` keys plus `frames` and `fps`. Custom mode has firmware status `requires_build`, compatible=false, no claim of a matching bit. Frozen changes use exact frozen ROM, compatible=false and explicit `differences`; frontend always displays this mismatch. `release.json` is published atomically only on complete success; failed/cancelled outputs have no valid release manifest.

After offsets/splitting, lyric timestamps must be strictly increasing within `0..262143 ms` (18-bit ROM field). Test both 262143 acceptance and 262144 rejection, including negative offsets. Do not silently truncate or widen RTL.

## Chunk 3: Local application and SD operations

### Task 4: Project/API server and media streaming

Files: `src/studio/{server,jobs,devices}.py`, `src/launcher.py`, `tests/test_{server,devices}.py`.

Exact routes, JSON responses and shared identifiers (project/release/job ids are validated server-generated directory identifiers; all mutations require session token in `X-Studio-Token`):

| Method + route | Request | Response |
|---|---|---|
| GET `/api/state` | — | `{projects:[{id,name}], jobs:[], version, profile}` |
| POST `/api/projects` | `{name}` | `{id, project}` |
| GET `/api/projects/{id}` | — | `{id, project, releases:[{id,release}]}` |
| PUT `/api/projects/{id}` | project object | `{id,project}` |
| POST `/api/projects/{id}/upload?name=...` | raw streamed file bytes; Content-Length required | `{path:"inputs/<uuid>.<ext>", name, bytes}` |
| GET `/api/projects/{id}/asset?path=...` | validated project input path | file bytes |
| POST `/api/projects/{id}/build` | `{}` | `{job:id}` |
| GET `/api/jobs/{id}` | — | `{id,status,stage,fraction,message,error,result}` |
| POST `/api/jobs/{id}/cancel` | `{}` | `{ok:true}` |
| POST `/api/projects/{id}/releases/{release}/verify` | `{}` | `{job:id}` |
| GET `/api/projects/{id}/releases/{release}/frame?track=0&time_ms=0&page=play&background=0&visual=mv&brightness=3&contrast=2` | — | PNG640×480 |
| GET `/api/projects/{id}/releases/{release}/audio?track=0` | optional single byte Range | WAV header + image PCM range; 200/206/416 |
| GET `/api/disks` | — | `{disks:[full identity snapshots]}` |
| POST `/api/disks/diagnose` | `{project:id,release:id,disk:full_snapshot}` | `{job:id}` |
| POST `/api/disks/write` | `{project:id,release:id,disk:full_snapshot,confirm:"ERASE n bytes"}` | `{job:id}`; UAC helper |
| POST `/api/open-output` | `{project:id,release:id}` | `{ok:true}` |

The server validates Host on every request and Origin on all browser mutations, rejects path escape and unsupported content types. The elevated writer repeats `require_same_device(snapshot,current)` before delegating to physical writer; the existing physical writer independently rechecks identity again at lock/open/write/readback boundaries. Development calls only list/diagnose/file simulation.

- [x] Tests first: session token+Host/Origin checks for mutation routes, path traversal rejection, stale build versus edited project, range WAV response, immutable output selection, device identity mismatch and source-disk refusal.
- [x] Implement loopback server with random session token/port, streamed uploads, JSON project save/load, list/open results, asynchronous build/verify jobs, preview PNG API and WAV ranges from final PCM.
- [x] Device operations reuse vendor safe_raw_writer; diagnosis is read-only, writes require exact selected-device confirmation and elevated helper, helper rechecks image/hash/device metadata itself. No physical disk is written during development tests.
- [x] Simulated file write/readback proves entire image SHA; tests verify no system/source/different-disk escape.
